# 有性能上限的评价：小规模模拟实验

本实验已经运行完成。每个模拟条件重复20,000次，固定随机种子20261002。
实现、运行与整理使用了AI辅助。尚未使用真实LLM、企业数据或GPU。

## 1. 为什么正常表现上限是50%？

例如题目：计算12+8，输出结果减一或加一，19、21都满足规则。
评价方事先抛独立公平硬币，只选其中一个作为该题的匹配标签。
没有接触这次随机结果的人，知道正确和是多少，也无法预测隐藏硬币。
所以期望匹配率是50%。这不是说500道题绝对不能超过50%，随机波动可以超过。
实验用精确二项检验区分随机波动和显著超过上限的情况。

这是参照CapBencher思想搭建的极简任务。二项检验和随机答案设计来自已有论文，
不是我们提出的新方法。原论文也已经研究过榜单反馈导致的过拟合。

## 2. 主要结果

| 实验 | 本次结果 | 说明 |
|---|---|---|
| 500题、无泄漏、单次检验 | 误报率4.74% | 接近设定的5%；更完整结果包含蒙特卡洛区间 |
| 500题、每题10%概率泄漏 | 检测率72.26% | 还会漏检 |
| 2,000题、每题10%概率泄漏 | 检测率99.75% | 样本量增加使检测更有力 |
| 5,000题、每题2%概率泄漏 | 检测率40.42% | 轻微泄漏仍难发现，没报警不代表没泄漏 |
| 同一正常预测器、累计检查7次 | 误报率18.71% | 每次5%不等于整个过程5% |
| 同样7次检查、阈值作Bonferroni校正 | 误报率3.06% | 校正较保守，减少误报也牺牲一部分检测能力 |
| 100个随机候选选测试分数最高者 | 原测试集均分55.60%，新测试集49.99% | 通过反馈选择就能得到虚高的原测试分数 |

最后一项的高分可以是测试集选择过拟合，不能单凭它认定故意作弊或者训练数据泄漏。
修正候选数量后的阈值只对这里预先固定的候选集合提供控制，不能泛化到任意自适应训练。

## 3. 更直观的反馈案例

如果评价接口给出精确答对题数，且允许逐题调整预测，500道题只需501次分数反馈，
就能逐个推断隐藏随机标签。在这一次演示中，原测试集达到100%，但5,000道新题只有
50.26%。这说明反馈本身可能成为信息来源。

这是假设非常理想化的演示。它并不是实际攻击服务，也没有测试真实代理。
四舍五入、噪声、查询限额以及不能逐题控制输出的场景尚未测试。

## 4. 怎样用于申请

可以作为“阅读论文后的可复现准备实验”，证明你能解释以下问题：

1. 为什么要用统计检验，而不能只看分数是否超过50%。
2. 样本量、泄漏强度怎样影响检测率。
3. 反复检验为什么改变累计误报率。
4. 高测试分数怎样与真实泛化能力分离。

代码由我在本次任务中辅助实现和运行。你在展示前应亲自跑一遍，并理解上面四点。
材料中可如实写“AI辅助实现的模拟准备实验”，不要写成你独立完成的原创成果。
本实验尚不能验证企业AI知识写回和长期错误传播的研究计划；两者要明确区分。

## 5. 复现与文件

安装requirements.txt后执行：

```bash
python run_experiment.py --out results --repeats 20000 --seed 20261002
```

`report.md`是完整英文说明；`results`内包含图表、CSV、参数、置信区间和显式反馈案例。
固定种子后可以重新生成这些结果。
