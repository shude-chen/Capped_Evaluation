# 有性能上限的评价：小规模模拟实验

这是一项关于 AI 评价统计可靠性的可复现合成实验，参考了 Ishida 等人在 CapBencher（ICML 2026）中的随机答案设计。所有模拟条件各运行 20,000 次，固定随机种子为 20261002。代码实现、运行和文档整理使用了 AI 辅助。实验没有使用真实 LLM、企业数据或 GPU。

## 1. 为什么期望匹配率上限是 50%？

例如，题目要求计算 12+8，并允许把正确和减一或加一作为答案，因此 19 和 21 都满足规则。评价方对每道题独立抛一枚公平硬币，秘密选出一个作为匹配标签。不能接触这一随机结果的预测器即使知道正确的算术结果，也无法预测隐藏硬币，因此期望匹配率为 50%。

50% 是期望值，而不是任何有限样本都绝不能超过的硬上限。实验使用单侧精确二项检验，判断观测分数是否显著高于这一基准。该设计与基础统计检验来自既有研究，并非本项目提出的新方法。

## 2. 主要结果

| 实验 | 测得结果 | 说明 |
|---|---|---|
| 500 题、无泄漏、单次检验 | 报警率 4.74% | 接近名义 5% 显著性水平 |
| 500 题、每题 10% 概率泄漏 | 检测率 72.26% | 部分泄漏仍会漏检 |
| 2,000 题、每题 10% 概率泄漏 | 检测率 99.75% | 样本量增加有助于检出泄漏 |
| 5,000 题、每题 2% 概率泄漏 | 检测率 40.42% | 弱泄漏仍然难以检测 |
| 同一正常预测器累计检验 7 次 | 累计误报率 18.71% | 每次单独使用 5% 不等于全过程控制在 5% |
| 上述 7 次检验进行 Bonferroni 校正 | 累计误报率 3.06% | 降低误报的同时可能降低检出能力 |
| 从 100 个固定随机候选中选择最高分 | 复用测试集 55.60%，新测试集 49.99% | 测试反馈选择带来表面分数升高 |

最后一项体现的是**测试集选择过拟合**。不能仅凭复用测试集上的高分认定训练数据泄漏或故意作弊。针对预先固定候选集合的多重检验修正，也不能直接推广到任意自适应训练场景。

## 3. 精确分数反馈的理想化例子

如果评价接口返回精确的答对题数，并允许逐题调整预测，那么在一个包含 500 道题的简化场景中，先获得一次基线分数，再分别修改一个预测，就可以使用共 501 次分数反馈推断出全部隐藏随机标签。这一次演示的复用测试集匹配率达到 100%，但在 5,000 个新题 ID 上，固定默认回答仅达到 50.26%。

这个例子说明详细反馈可能泄露关于隐藏标签的信息，但假设了无限制查询、精确分数和逐题控制。它不代表真实 LLM 服务或多智能体系统，也不是对外部服务的实际攻击。

## 4. 实验意义与局限

实验在可控条件下说明：有限样本分数波动不等于真实泛化能力提高；弱泄漏不一定被检出；重复检验可能提高累计误报率；依据测试反馈反复选择模型，可能使复用测试集上的成绩虚高。

这些结论依赖独立随机标签、已知期望匹配率以及简化的评价与反馈机制。实验没有真实运行 LLM 或多智能体工作流，也没有测试工作流错误传播、选择性验证或人类反馈。因此不能将结果视为这些系统已经得到验证的证据。

本项目使用了 AI 辅助实现与整理，全部方法、代码和结果均可检查。基础统计设计归功于 CapBencher 等既有研究；本实验旨在帮助理解评价偏差与统计方法的适用边界。

## 5. 复现与文件

安装 `requirements.txt` 后运行：

```bash
python run_experiment.py --out results --repeats 20000 --seed 20261002
```

`report.md` 提供完整英文报告；`METHODS.md` 说明方法和统计假设；`results/` 包含图表、CSV、参数、置信区间及显式反馈演示。固定随机种子可复现已有数值结果。建议使用独立输出目录，避免覆盖仓库自带的结果。
